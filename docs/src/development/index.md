# Core principles

1. **One workflow authority.** Beads determines what exists, what is blocked, and what is ready.
2. **Ask before encoding policy.** Planning identifies material ambiguity and asks the user before finalizing intent.
3. **Independent review before approval.** Review checks the plan against code, tests, current documentation, and prior
   decisions before tasks are approved.
4. **Documentation is implementation.** A task owns the current documentation needed to explain its accepted behavior to
   each affected audience.
5. **Audit from evidence, not memory.** Final review compares approved intent, native tasks, reachable Git history,
   tests, code, and documentation.
6. **Automate only deterministic mechanics.** dStack formats, validates, and verifies; skills make semantic judgments.
