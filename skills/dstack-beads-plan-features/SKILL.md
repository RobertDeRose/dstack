# Plan features

Analyze product goals, existing design patterns, implemented behavior, and
known gaps. Create or update Beads feature ideas/tasks and real dependencies.

Repository planning documentation may describe durable `planned`,
`implemented`, or `deprecated` product context, including why a feature exists
and its stable dependencies. It must not contain in-progress/review/blocked/
delivery-ready state, Beads or gate IDs, branch/commit data, or next commands.

Do not start a feature, create branches/worktrees, or create lifecycle ceremony.
Return prioritized feature ideas, dependencies, unresolved product decisions,
and which feature is the best next candidate.
